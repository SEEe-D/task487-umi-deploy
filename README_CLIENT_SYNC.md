# Task487 普通同步推理 / 作者式 Bézier 执行

新增入口：`run_task487_client_sync.sh`。复用现有 Task487 的权重契约、真实反馈、
相机和夹爪标定，把执行调度换成作者普通版的思路；不是整包覆盖 `eval_mink_new`。
原 `run_task487_client.sh` 默认仍使用原 rolling 调度，可以直接回退。

2026-09-05 连续衔接修复：保留旧轨迹到未来衔接点再接新块；轻微超速改为最多 150 ms
局部时间修正。不是取消限速，也不是等整个动作块执行结束后才重规划。

## 使用

底层继续用现有 `/home/simpleai/Code/mjm/eval_mink` 的栈，服务端继续使用现有
`run_task487_server.sh` 及所选权重；不启动作者包的底层或 `run_pi05_rtc_e2e.sh`。
普通模式只调用标准 WebSocket infer，不发送动作前缀，不要求 RTC 能力字段。
服务器即使支持 RTC，也不会因本客户端而收到 RTC prefill 请求。

默认半速播放，双臂平移上限 0.15 m/s、旋转上限 0.35 rad/s。先做短段验证：

```bash
cd /home/simpleai/Code/universal_manipulation_interface-main/gj/pi05-deploy
./run_task487_client_sync.sh sorting 127.0.0.1 8000 \
  --execute --sync-speed-scale 0.5 \
  --sync-max-pos-speed 0.15 --sync-max-rot-speed 0.35
```

启动停在 HOLD；需要时按 `r` 执行 HOME 和夹爪准备，按 `d` 开始，默认最多下发 5 个
重采样路点后 HOLD；`s` 暂停，Ctrl+C 退出。HOME 是明确的硬件运动指令。
保持工作空间清空并准备硬件急停；本次没有验证新速度下的真机安全或抓取成功率。

短段确认正常后，同一命令增加 `--continuous` 可连续运行。
这次修改包括客户端创建的控制器子进程，必须退出旧客户端后重启；模型服务与独立
`eval_mink` 后端没有改动，无需为本次代码更新重启它们。
不传上述三个参数也采用这组慢速默认值。旧命令显式传入的 `0.5/0.5` 会覆盖新的限速默认值，
需要替换为 `0.15/0.35`。`--sync-speed-scale` 范围为 `(0,1]`，越小越慢；
它延长轨迹时间，不缩放位置、姿态或夹爪角度。`1` 恢复原播放时间，速度上限仍独立生效。
速度参数仍是实际 m/s、rad/s 上限，不会再乘播放倍率或 `sqrt(3)`。
原作者上限 0.606 m/s、1.732 rad/s 仅作为参数最大允许值，不再是客户端默认值。

不传 `--execute` 时不下发 policy 动作或 HOME，但仍需要真实相机/机器人反馈，
这不是无硬件仿真，也不要与其他执行客户端同时连接。

三组现有 4w runtime 会把 vegetable/fruit 别名解析为训练中的排序 prompt；
相机、频率、horizon、图像预处理仍以服务端的已验证 runtime 为准。
当前原始/纯真机旧组的不同接口也保持原规则；未知 runtime 仍拒绝启动。
新 WRC 训练工程的权重不因新增此入口而自动获得部署适配。

## 实现和与作者原版的区别

- `task487_runtime/author_sync.py`：普通动作 chunk → 过期前缀剔除 → cubic Bézier 位置、
  SLERP 姿态连接 → 连续未来路点。无 RTC 前缀或旧尾段加权混合，不调用原 rolling 重定时。
- 网络请求使用单个后台 worker，仅为了等待网络时继续处理停止键；每次仍是普通 infer，
  没有引用作者包外的 `RTCInferenceClient`。
- 每 6 个训练时间步请求一次；12.5 Hz 时名义间隔 0.48 秒，25 Hz 时为 0.24 秒。
  使用固定周期截止时间，避免浮点误差和慢 tick 让周期逐轮漂移。若推理更慢则等待当前请求，
  不并发堆请求。无动作可执行或请求超过 2 秒会 HOLD。
- 默认每个名义时间间隔延长到两倍，与真实夹爪行程所需时间取最大值，再满足双臂限速。
  夹爪已受行程限制的慢段不会再机械地延长两倍。观测过期判断、设备时延及重规划周期保持真实时间。
- 每次提交最多 `(6+1)*dt + 0.15s` 的物理轨迹，以留出推理重叠；慢放和夹爪重定时后也按这个窗口截取。
- 使用作者普通文件的设备时延设置：机械臂 0.11 秒、夹爪 0.176 秒。
  共用物理目标时间，下发时各自减去设备时延。它们不是本次重新实测的硬件时延。
- 首块从真实控制器目标连接；后续块从已提交轨迹在**未来衔接点**的位置与运动方向连接。
  `UmiEnv` 将 `replace_from_time` 分别减去设备时延，只附在每个设备新块的第一点；
  插值器保留此前仍在运动的旧轨迹，不再每轮清空到当前时刻后重新慢起步。
  这比直接复制作者当前位姿锚点更严格地处理了未来下发延时，不能宣称速度 / 加速度完全连续。
  插值保留夹爪原始节点，执行窗口内的完整节点不因位置连接而跳过；窗口外继续重规划。
  夹爪不做任务相关 1.3 倍或重复 1.2 倍增益。
- 保留当前右 34°/左 24° 的独立安全端点、角度一一映射。规划和夹爪控制器统一读取后端
  `gripper_can.yaml` 的电机速度：当前 3 rad/s ÷ 减速比 20，得到 **8.594°/s**。
  双臂和夹爪共享满足开合行程的到达时间。手臂额外重定时仍限 150 ms，物理限速/跟踪保护保留。
  其他后端配置路径用 `--gripper-config` 指定；启动日志会打印读取的路径和速度。
  超端点仍裁剪，CAN 速度/限矩未提高。
- 不沿用作者自动 HOME、零位姿/closed 假反馈、遥控器子任务覆盖或仅 pose6 的旧 UDP 协议。
- 保留现有 step/tracking/非有限数检查；Bézier 生成后再检查，必要时只延长超限小段，
  双臂及夹爪共享修正后的目标时间。除主动慢放和夹爪行程外，手臂累计额外修正不超过 150 ms；超预算仍 HOLD，
  报错给出当前段双臂平移 / 旋转速度与上限。不会把新块排到整块旧轨迹尾端。
  `retimed` / `max_delay` 记录修正；下一次重规划截止时间独立，不等待修正轨迹播完。
  夹爪控制器使用从 CAN 配置读取的 8.594°/s 限制，不能保证更快开闭。
  当前部署的绝对桌面高度保护原本关闭，本次没有增加或承诺碰撞检测。
- 退出/异常增加最终 HOLD；五点模式限制实际提交数量，不仅是事后数到五点才停止。
  共享 worker 现在拒绝积压请求，上一轮结果必须先取出并按 round_id 丢弃，才允许新请求。

控制模式和有效上限打印在 client.log 中；继续保留 policy_chunks、chunk_diagnostics.jsonl、
控制器 CSV。诊断结构沿用旧字段，普通模式 `rtc_prefix=0` 不代表启用了 RTC。
日志目录仍是 `task487_logs/<本次运行>/`。

## 5°补偿 v2：反馈坐标及右手先放行（2026-09-05）

18:58 试用暴露了闭环问题：原始实测开度变小后，模型下一轮也预测更小的角度，再减 5°会持续收紧。
新版为每个夹爪同步维护模型参考与实体目标，二者沿同一段控制器时间插值：

`模型等效开度 = 模型参考开度 + 实测实体开度 - 实体目标开度`

例如参考 12.8°、实体目标 7.8°、实测 7.8°时，模型输入是 12.8°；
若物体挡住后实测为 10°，模型输入是 15°，保留 2.2°跟随误差，不能伪装为已到目标。
这是已知执行偏置的坐标换算，不是新的指尖宽度/夹持力标定。无补偿时继续使用原始实测开度。
换向、限位裁剪和重新衔接时使用本次实际下发的偏置，而不是对反馈机械地加减固定 5°。

专用 `run_task487_client_sync_gripper5.sh` 现同时开启 `--sync-right-before-left`：
左臂和左夹爪先保持在启动位置；右手经历打开、闭合，再转为打开之后，实测开度到达记录的打开目标
