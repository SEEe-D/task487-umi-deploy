# 双手闭合 / 张开各 5°补偿试用

2026-09-05，用户要求“夹紧张开都补偿 5 度试一下”。按双手均生效实现，提供独立试用入口，当前普通入口默认仍为 0。

- `--sync-gripper-close-compensation-deg 5`：明确闭合时，原始绝对开度减 5°。
- `--sync-gripper-open-compensation-deg 5`：明确打开时，原始绝对开度加 5°。
- 两手各自判断开合方向；同方向的平台继续补偿，但对原始模型值只应用一次，不对上轮补偿命令再次叠加。
- 0.5°原始请求反转门槛；初始化为未定方向，启动静止不会直接多开 5°。仅首个未过期请求推进跨块状态；
  远期预测只在本块预览，拒绝块不提交状态，重新 ACTIVE 初始化。模型看到的仍是真实夹爪反馈。
- 开度限制为右手 `[0,34°]`、左手 `[0,约24.035°]`，来自客户端现有验证端点。接近端点时补偿会被截断。
- 不与旧右手 0–2°闭合补偿叠加；非零新补偿仅 author-sync 支持。范围、物理限位、夹爪速度配置均在启动时校验。

启动试用：

```bash
cd /home/simpleai/Code/universal_manipulation_interface-main/gj/pi05-deploy
bash run_task487_client_sync_gripper5.sh sorting 127.0.0.1 8000 --execute --continuous
```

启动仍在 HOLD，按 `r` HOME+准备后，按 `d` 开始；`s` HOLD。
日志应显示 `Both grippers compensation: closing=-5.00deg opening=+5.00deg`。
恢复无补偿使用原 `run_task487_client_sync.sh`，不带新旧补偿参数。

## 时序与日志

额外行程与手臂一起重定时，夹爪仍不超过 8.594°/s，双臂默认仍为 0.15 m/s、0.35 rad/s、半速。
单独 5°行程至少约 0.58 秒；方向偏置从 -5°变为 +5°增加 10°行程，其耗时至少约 1.16 秒。
实际过程叠加原始动作变化，且受不断更新的观测/模型目标影响，不能将这些下限视为固定执行延迟。
0.71 s 物理提交窗口、连续前缀、既有衔接/跟踪检查均保留。后端力矩上限与堵转保护未改。

启动日志明确给出双方向补偿量及各手端点；`policy_io.jsonl` 会话 metadata 的配置保存新参数。
原始响应、`raw_targets` 保留，`post_queue_targets` 和夹爪 trace 记录补偿并重定时后的目标，可与连续实测角度/力矩对齐。

## 验证与限制

**189 项离线测试通过**。新增检查覆盖双手相反方向、初始中性状态、平台不累加、方向反转、上下限、参数互斥、
过期/远期预测、拒绝块不提交状态、重新激活，以及两个真实夹爪插值器在 ±5°切换下的限速、前缀保持和共同时间。
测试输出在 `pytest.txt`。

真实记录经四个生产插值器离线回放（双臂相对动作按模拟 TCP 重绑定，夹爪保留旧绝对预测）：

**5°补偿确实可能让较慢的开合拖慢共同路径，并更早遇到机械臂衔接保护。** 这项回放发现已告知用户，未放宽阈值。
回放使用旧观测对应的预测，不会生成补偿后新画面的模型动作，也不模拟物体接触；不能推断实机必然在相同段停止或能夹牢。

代码及离线验证已完成；没有启动自动抓取、修改后端参数、重启进程或发布机器人动作。实物效果待用户使用专用入口试运行。
