# Task487 raw 12.5 Hz dataset/deployment audit (2026-08-18)

## Scope

- Full new UMI dataset: 1,500 episodes, 401,510 rows, 12.5 Hz.
- Local pure-real sample: 6 episodes, 4,407 rows, 25 Hz. Full-dataset value
  statistics are also available in the checkpoint norm stats.
- Read-only checks only; no robot commands were published.

## Findings

### 1. Gripper units and direction are correct

Both datasets store the gripper value in radians with `0 = closed` and larger
values = more open. A visual check of UMI episode 0 matched the telemetry:
right gripper 1.14 degrees was closed and 35.24 degrees was open. Therefore the
deployment's direct `rad2deg` output conversion is the intended mapping; it
must not be inverted or quantile-rescaled.

### 2. The 12.5 Hz action labels are not shifted or corrupted

For every one of the 400,010 nonterminal rows:

```text
action[t] == observation.state[t + 1]
```

The maximum absolute error was exactly 0 across all 20 dimensions. Every
terminal action also exactly repeated its terminal state. This rules out an
off-by-one error in the conversion/downsampling action labels.

The UMI data contains substantial gripper motion:

| Metric | Right | Left |
|---|---:|---:|
| Episodes with range >5 degrees | 99.73% | 99.87% |
| Episodes with range >10 degrees | 85.93% | 97.07% |
| 20-step windows with range >5 degrees | 16.84% | 19.41% |
| 20-step windows with range >10 degrees | 8.69% | 12.13% |
| 20-step windows closing by >5 degrees | 8.54% | 9.34% |
| 20-step windows opening by >5 degrees | 8.08% | 9.88% |

About 87--88% of UMI single steps move less than 0.1 degree, but the pure-real
sample is similarly sparse (about 90--93%). The downsampling did not erase the
open/close events.

### 3. High-impact gripper-state convention gap

The UMI demonstrations start and end with both grippers almost closed, while
the pure-real deployment starts and ends with both grippers open:

| Dataset | Right start median | Left start median | Right end median | Left end median |
|---|---:|---:|---:|---:|
| UMI 12.5 Hz | 0.97 deg | 0.79 deg | 1.01 deg | 0.88 deg |
| Pure-real sample | 34.86 deg | 34.88 deg | 34.86 deg | 34.89 deg |

The inactive arm also follows opposite task protocol (not opposite angle
direction):

| Task | Dataset | Inactive arm | <=3 deg | >=30 deg |
|---|---|---|---:|---:|
| Vegetable/right arm active | UMI | Left | 90.0% | 0.5% |
| Vegetable/right arm active | Pure real | Left | 0.0% | 100.0% |
| Fruit/left arm active | UMI | Right | 90.8% | 0.0% |
| Fruit/left arm active | Pure real | Right | 0.0% | 100.0% |

The raw checkpoint is therefore trained mostly on a closed-idle/closed-boundary
protocol, but deployment HOME supplies 35/35 degrees. Since relative-state
processing keeps both gripper values absolute, this is a real input-domain
shift, not merely a logging difference.

### 4. High-impact image geometry mismatch

All three new UMI raw training streams are 280x224. The model transform uses
`resize_with_pad` to produce 224x224, preserving the entire 1.25:1 field of
view as a 224x179 image with black padding above and below.

The current real client instead center-crops every 640x512 stream to 512x512
and then resizes it to 224x224, discarding 64 pixels from each horizontal edge.
This matches the older pure-real dataset, but not the new raw UMI dataset.
Thus the same client geometry cannot faithfully serve both checkpoints.

### 5. Vegetable prompt mismatch

New UMI training task:

```text
Pick Up Vegetable and Place Vegetable on the Pink Plate on the Right
```

Current client / old pure-real task:

```text
Pick Up Vegetable and Place Vegetable on the Pink  Plate on the Right
```

The PaliGemma tokenizer does not collapse the extra space. With the Pi0.5 state
in the prompt, the sequences have lengths 104 and 105 and first differ at token
position 12. The fruit prompt is not affected by this particular mismatch.

## Conclusion

The audit does not support "gripper labels disappeared during downsampling" or
"rad/degree conversion is wrong." It finds concrete deployment-domain
mismatches for the new raw checkpoint: image geometry, HOME/inactive-gripper
protocol, and the vegetable prompt. These should be corrected and A/B tested
before judging the new checkpoint's training quality or retraining it.

## Implemented deployment fix

The client now selects these conventions from the server-advertised runtime:

- raw 12.5 Hz uses full-FOV `resize_with_pad`, the single-space vegetable
  prompt, and a 1/1-degree HOME gripper boundary state;
- older pure-real/B1 runtimes keep center-square cropping, their original
  double-space vegetable prompt, and the 35/35-degree open HOME state.

The model output remains a direct radians-to-degrees command. No inversion,
quantile mapping, or learned-output rescaling was introduced.
